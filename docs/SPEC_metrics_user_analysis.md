# SPEC: Метрики — «Анализ пользователей»

> Подраздел Статистики на сайте. Точечный анализ юзеров по образцу ChatKeeper.
> Дата составления: **2026-05-24**. Триггер: Илья прислал 23 скрина ChatKeeper.
> Решение по срокам: **отложить до 2026-05-27 (среда)** и тогда планировать запуск.

## 1. Зачем

Текущая Статистика (StatsPage) даёт **агрегаты по чату** (11 виджетов: пользователи, сообщения, вовлечённость и т.д.). «Метрики» — это **второй уровень**: разрез **per-user**, конструктор показателей и детальная страница на одного человека. Закрывает кейсы «найти топ-токсиков», «понять чем занят конкретный юзер», «увидеть граф взаимодействий».

## 2. Структура экрана

### 2.1 Главный экран — конструктор + таблица

**Шапка-фильтры:**
- Диапазон дат **С / По**
- **Группировка:** Дням / Неделям / Месяцам / Годам / Без группировки
- **Когорта «Активность за период»:** Писали сообщения / Вступили в группу / Покинули группу
- Поиск по `ID` или `@username`

**Конструктор метрик:**
- Кнопка `+ Добавить метрику` → модалка с каталогом
- Лимит: **до 5 одновременно**
- Каждая выбранная = карточка-сводка (название + «Всего: N» + микро-бар) с уникальным цветом
- Можно удалить (×) и переставлять

**Таблица топ-юзеров:**
- Колонка «Пользователь» — аватар + имя + `@username` + полоса периода активности
- На каждую выбранную метрику — колонка с мини-баром на юзера
- Hover на баре: tooltip с **датой/периодом + точным значением**
- Сортировка по любой метрике (стрелки в шапке)
- В режиме «Без группировки» — вместо бара одно число (рейтинг)

### 2.2 Каталог метрик (модалка)

Категории (взято из ChatKeeper, к нашему стеку):

| Категория | Метрики ChatKeeper | Наш статус |
|---|---|---|
| **Сообщения** | Сообщения, Ответы на сообщения | ✅ есть |
| **Очки** | Получено/выдано опыта, действий, репутации | ✅ опыт/действия (XP/Пульсы), ❌ репутация |
| **Наказания** | Получено/выдано: предупреждения, баны, муты | ✅ warnings (счётчик), 🟡 баны/муты (только флаги) |
| **Реакции** | 10 разных | 🟡 только суммы (received/given) |
| **Другое** | Триггеры вызвано, токсичность | ✅ триггеры, ❌ токсичность |

У каждой метрики — `?` подсказка с описанием и примером применения (как у ChatKeeper).

### 2.3 Детальная страница юзера (по клику в таблице) = админская витрина #9 Профиля-паспорта

> **Архитектурное решение Ильи 24.05:** страница юзера в Метриках — это **тот же Профиль-паспорт #9, что в боте**, но **расширенный со стороны владельца/админа**. Не отдельная сущность — другая витрина одних данных.

**Принцип трёх витрин одних данных:**
| Витрина | Кто смотрит | Что показывает |
|---|---|---|
| Бот `/profile` (#9) | Юзер сам себя | Паспорт + Кошелёк + Активность сегодня + BBS-сводка + кнопки действий |
| **Сайт → Метрики → клик по юзеру** | Владелец/админ | Всё то же + админский слой (Trust Index, наказания, граф взаимодействий, лента событий, кнопки модерации) |
| (будущее) Публичная карточка | Все | Самый узкий слой (имя, ранг, ачивки) |

**Каркас наследуется от #9** — Паспорт / Кошелёк / Активность / BBS. **Админский слой добавляется сверху:**
- Блок «Око Пульса»: Trust Index 0–100, timeline снижений/искуплений, текущая санкция, кнопки `Простить +50` / `Осудить −50` (см. §9)
- Блок «Взаимодействие пользователя»: с кем общается, токсичность %, реакции (см. ниже)
- Блок «Лента событий»: triggers, наказания, команды, выдача XP (см. ниже)
- Кнопки модерации: warn / mute / ban / remove from chat
- Метрики per-юзер: все 13 готовых + (после реализации) Trust Index и наказания

**Шапка:** `← Назад`, имя, период С/По.

**Левая колонка:**
- Аватар + имя + `@username` + `(user_id)`
- 📅 Дней в чате · «Вступил с …»
- 🏆 Ранг / XP / AP / бейджи репутации
- Кнопка `Telegram-профиль`

**Правая колонка (быстрые числа):**
- Сообщений
- Дней писал · «Первое сообщение от …»
- Последнее сообщение + кнопка «Просмотр сообщения» (deeplink в TG)
- Банов через фильтры
- Предупреждений
- Достижения (раскрываемое; у нас — Титулы/VIP/бейджи)

**Графики:**
- **Сообщений по дням недели** (Пн-Вс, выходные выделены)
- **Сообщений по часам** (0..23)
- **Сообщения** — большой stacked-bar (свои + ответы)

**Блок «Взаимодействие пользователя»:**
- Таблица: `Собеседник | {Имя} взаимодействовал | С {Имя} взаимодействовали`
- В каждой строке: количество сообщений, реакции с бейджами, токсичность %

**Лента «События в группе, связанные с {Имя}»:**
- Timeline: триггеры, наказания, команды, выдача XP/AP

## 4. Ограничения — что НЕ сможем реализовать или с оговорками

| Метрика | Ограничение |
|---|---|
| **Реакции по типам (10 метрик)** | TG API: `MessageReactionUpdated` приходит боту **только если он админ** и **только для новых реакций после включения слушателя**. Исторических данных нет (как и у ChatKeeper). Можно сделать с нуля. |
| **«На сколько сообщений поставлено/получено реакций»** | Нужна таблица уникальных `message_id` с реакциями — может быть большой; нужно решить TTL. |
| **Токсичность %** | ChatKeeper использует AI/ML классификатор текста. Варианты для нас: (1) внешний LLM (OpenAI/Anthropic — деньги за каждое сообщение); (2) self-hosted opensource (хостинг $$); (3) **эвристика «доля сообщений с warning + удалённые»** — дёшево, реалистично, **рекомендуется**. |
| **Дип-линк «Просмотр сообщения»** | Для **приватных супергрупп** `t.me/c/{chat_id}/{message_id}` открывается только участниками группы. Веб-юзер без TG-доступа к чату — не откроет. Это TG-ограничение. |
| **«Достижения» страницы юзера** | У нас своя система (Титулы/VIP/Ранг/AP) — она не мапится 1:1 на ChatKeeper. Показываем нашу. |

## 9. Око Пульса как центр наказаний внутри Метрик (решено 24.05)

Изначально #11 «Око Пульса» из `docs/IDEAS_BACKLOG.md` рассматривался как отдельная подсистема. **Решение 24.05:** Око и Метрики — это **одна подсистема «наблюдение за поведением»**, где:

| Слой | Что | Куда смотрит |
|---|---|---|
| **Око Пульса (бэк)** | Детекторы поведения + Trust Index (0–100) + санкции + AI-классификатор | Внутрь — бот сам реагирует на нарушения |
| **Метрики (фронт)** | UI-витрина того, что считает Око: токсичность, наказания, причины | Наружу — владелец видит и принимает решения |

**Что это меняет для Метрик:**
1. Блок «Око Пульса» на странице юзера в Метриках:
   - Trust Index 0–100 (полоска с цветом по диапазону)
   - История изменений Trust (timeline: «−15 карусель донатов 12.03», «+10 польза в ПлюсON 14.03»)
   - Текущая санкция (если есть): «×0.5 майнинг» / «налог /pay» / «шэдоубан»
   - Кнопки владельца: `Простить +50` / `Осудить −50` / «Настроить чувствительность ИИ»
2. Метрика «Токсичность %» в каталоге → **вычисляется Оком** (не отдельной эвристикой). Если Око не запущено — fallback на эвристику «warnings / messages».
3. Метрика «Получено наказаний» / «Получено предупреждений» → читается из таблицы `moderation_log` (она же — источник истории изменений Trust).
4. Колонка «Trust Index» появляется как стандартная метрика в каталоге.

**Эволюционный путь:**
```
Стадия 1 (вместе с Метриками V1):
  └─ moderation_log таблица + базовые детекторы (warn/mute/ban счётчики)
  └─ Trust Index = простая формула (warnings/messages × коэффициент)
  └─ Витрина в Метриках: метрики «получено/выдано наказаний», токсичность% эвристикой

Стадия 2 (Око Пульса P2, после движка #0):
  └─ Полный набор детекторов (карусель донатов, ферма реакций, синт-флуд, не-в-ту-дверь)
  └─ AI-классификатор токсичности через Groq/Gemini Flash
  └─ Теневые санкции с порогами + путь искупления (+5/день, +10 ПлюсON, +15 за 1000💎)
  └─ Блок «Око Пульса» на странице юзера + Trust timeline + кнопки Простить/Осудить
  └─ Панель Владельца [👁 Око Пульса] — топ-10 подозреваемых

Стадия 3 (когда движок #0 готов):
  └─ Око как полноценный модуль engagement-движка
  └─ Триггеры на пороги Trust в реестре objectives (можно цеплять награды/санкции через стандартный механизм)
```

**Архитектурное следствие:** таблицу `moderation_log`, которая в §3.2 была помечена как «нужна для Метрик», переименовываем в более общее `behavior_events` или `trust_events` — она работает одновременно на:
- Метрики (отображение)
- Око Пульса (вычисление Trust Index)
- Engagement engine (триггер objectives, если #0 готов)
