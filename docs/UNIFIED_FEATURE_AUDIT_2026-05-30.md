## 0. Главные выводы (TL;DR)

1. **Бот «Управление функциями» и сайт «Функции бота» — это ОДНА система, два экрана.**
   Оба пишут в одну таблицу `settings` ключами `feature_<id>` через `/api/features` ↔
   `setting_function_pr.py`. То, что списки на скринах совпадают 1-в-1 — не совпадение,
   это один backend.

2. **🔴 Эта система НЕ изолирована.** Таблица `settings` — глобальная (`WHERE key = ?`,
   без `workspace_id`, см. `database/db_settings.py:6-19`). Тумблер в одном workspace
   меняет состояние для **всех** workspace. Для SaaS это дыра.

3. **Параллельно живёт вторая, изолированная система — `module_toggles` (per-ws)** через
   хаб «Модули» (ModulesHub). В ней модулей **больше**, чем в legacy-списке бота (~36 vs 18),
   и она — современный источник правды для исполнения функций в боте
   (`is_module_enabled_cached`).

4. **Часть функций живёт в ОБЕИХ системах под РАЗНЫМИ id** → молчаливый рассинхрон:
   `top`↔`top5`, `donate`↔`donations`, `bbs`↔`bbs_pulse`, `bbs_edit`↔`bbs_anketa`.

5. Итог для многих функций: **видимость кнопки** в боте решает legacy-глобал (A),
   а **реальное исполнение** — per-ws `module_toggles` (B). Два живых гейта на одну функцию.

## 3. Разбор «болевых» классов

### 3.1 🔴 Только в legacy A, вообще не изолированы (5 функций)
`profile`, `bank`, `activities`, `detalization`, `registration`.
У них **нет** карточки-модуля в «Модулях». Единственный тумблер — глобальный `feature_*`.
Включил/выключил в одном ws → у всех. **Нет модуля → нет per-ws.**

### 3.2 ⚠️ Дубль с рассинхроном id (4 функции)
| Функция | id в A | id в B | Риск |
|---------|--------|--------|------|
| ТОП-5 | `top` (+`top_commands`) | `top5` | toggle B не влияет на видимость в боте |
| Донаты | `donate` | `donations` | toggle B не виден боту (бот читает A) |
| Pulse BBS | `bbs` | `bbs_pulse` | разные ключи, не синхронны |
| Ред.анкет BBS | `bbs_edit` | `bbs_anketa` | то же |

### 3.3 ⚠️ Дубль с одинаковым id, но двойной гейт
`statistics`, `lottery`, `bingo`, `monthly_gift`, `horoscope`, `referral`, `shipper`, `titles`,
`bbs_other`. Видимость кнопки в боте — A (глобал), исполнение — B (per-ws). Можно «включить
модуль» в ws, но кнопка не появится, пока глобальный `feature_*` = 1 (и наоборот, выключение
в другом ws потушит у всех через A).

### 3.4 🟢 Чисто per-ws (правильно)
`mining`, `sprints`, `combos`, `penalty`, `bbs_bonus`, `press_release`, `triggers`, `bbs_vip`,
`journal:*`. Это эталон — к нему надо привести всё.

## 4. Куда вести (предложение «единого пульта»)

**Цель:** один источник правды = `module_toggles` (per-ws), один экран-пульт, остальные —
зеркала/редиректы.

Шаги (черновик, обсудить с Ильёй):
1. **Завести модули для «сирот» A** (`profile`, `bank`, `activities`, `detalization`,
   `registration`) в `modules_catalog.json` → дать им per-ws тумблер.
2. **Свести id-дубли:** `top→top5`, `donate→donations`, `bbs→bbs_pulse`, `bbs_edit→bbs_anketa`
   (alias-мост на переходный период, чтобы старые ключи читались).
3. **`is_feature_enabled` → wrapper** на `is_module_enabled_cached(ws_id, module_id)`
   (legacy-ключи как fallback). Тогда видимость кнопок станет per-ws.
4. **Legacy-панель A** (бот + сайт «Функции бота») → либо убрать, либо сделать read-only
   зеркалом единого пульта.
5. **Единый экран** «Пульт функций» на сайте: все функции, секции, бейджи free/paid,
   состояние = `module_toggles`, cross-link в детальные настройки (Экономика и т.д.).

## 5. РЕШЕНИЯ Ильи 30.05 (зафиксировано)

1. **Единый источник = `module_toggles` (per-ws).** Управление функциями переезжает в раздел
   «Модули» и распределяется по карточкам. Цель — один пульт.
2. **Обе legacy-панели УБРАТЬ** — и бот «Управление функциями» (TG), и сайт «Функции бота».
3. **Регистрация** — НЕ примитивный тумблер: уедет в **Кузницу** (конструктор регистрации).
   Из списка «сирот» исключается.
4. **Центробанк** — системное ядро, всегда вкл (тумблера нет, остаются настройки банка).
5. **Профиль, Активности, Детализация** — становятся выключаемыми модулями.
6. **Ключевой принцип: видимость ≠ функция.**
   - **⚙️ Функция** — работает ли логика (начисления, реакции, посты).
   - **👁 Видимость** — показывать ли кнопку/раздел в боте.
   - Для большинства модулей это слито (один тумблер).
   - Для **пассивных коллекторов** (Статистика; вероятно Детализация/Активности-просмотр)
     сбор идёт всегда, тумблер управляет только показом → флаг `passive` в каталоге.

### 5.1 Паттерн «хаб-агрегатор» (видимость = OR вложенных функций)

**«Активности» — НЕ свой тумблер, а вычисляемый хаб.** Кнопка видна ⟺ включена хотя бы
одна вложенная функция: `donate OR referral OR lottery OR bingo OR monthly_gift`.
Всё выключено → кнопки нет; включил лотерею/рефералку → кнопка сразу появляется.

**Реализовано (30.05):**
- `database/db_settings.py` → `ACTIVITIES_CHILDREN` + `activities_visible(db)`.
- `db_manager.py` → метод `db.activities_visible()`.
- Заменено в 2 живых местах меню: `handlers/commands/system_commands.py`,
  `handlers/callback/callback_router.py`.
- Forward-compatible: когда `is_feature_enabled` станет обёрткой над per-ws
  `is_module_enabled_cached`, агрегатор автоматически станет per-ws.
- 🪦 Мёртвые дубли НЕ трогали: `handlers/utils/callback_handler.py`,
  `utils/callback_handler.py`, `utils/system_commands.py`.

Этот же паттерн применять к будущим хаб-кнопкам.
