# IDEA: База знаний — help-center продукта

> Запрос Ильи: 2026-05-24. Решение по фазе: **после Биллинга** (черновик; обсуждается возможность подвинуть раньше — см. §6).

## Что это

**Публичный help-center Pulse Bot** на нашем сайте. Документация по всем функциям бота для владельцев, админов и потенциальных клиентов. Не путать с базой знаний участников чата (контент про их тему) — это **наша внутренняя продуктовая документация наружу**.

**Не путать также с:**
- **Новости/Обновления** — хроника изменений (что недавно добавили)
- **Журнал** — события в чате (репортажи)
- **Триггеры** — точечные ответы бота
- **FAQ внутри Панели Владельца** — короткие подсказки рядом с настройками

База знаний = **постоянная справочная документация продукта**.

## Аудитория

| Кто | Зачем |
|---|---|
| **Владелец** | Как настроить функцию, что произойдёт если выключить модуль, какие тарифы |
| **Админ** | Какие у меня есть полномочия, как пользоваться панелью |
| **Потенциальный клиент** | Что умеет Pulse Bot, какие модули, сравнение с конкурентами |
| **Поисковик (SEO)** | Индексация: «как настроить экономику в Telegram-боте», «триггеры для админ-чата» |

## Структура

**3 уровня:** раздел → подраздел → статья.

**Примерный каркас разделов** (соответствует Хабу модулей):
1. **Старт** — что такое Pulse Bot, как подключить, первые шаги
2. **Сообщества** — workspaces, роли чатов (main/admin/journal), помощники
3. **Модули** — обзор каталога, тумблеры, free/paid, что внутри каждого
4. **Экономика** — Пульсы, mining, спринты, комбо, штрафы, лотерея, бинго, реферальная программа, BBS-бонусы, дефибриллятор, отмены выплат
5. **Триггеры** — создание, медиа, кнопки, кулдауны, лимиты
6. **Журнал** — категории, хештеги, формат записей
7. **BBS / VIP** — что это, как пользоваться, как давать титулы
8. **Гороскопы**
9. **Пресс-релизы** — шаблоны, брендинг, рассылки
10. **Статистика** — какие виджеты, как читать
11. **Метрики** — точечный анализ юзеров (после реализации)
12. **Регистрация-конструктор** (после реализации)
13. **Тарифы и биллинг** (после биллинга)

**Каждая статья содержит:**
- Заголовок + краткое описание (1 строка для поиска)
- Тело: текст + скриншоты + гифки/видео
- Блок «Что произойдёт если выключить» (для модулей/тумблеров)
- Блок «Связано с» — ссылки на смежные статьи и страницы в админке
- Дата обновления + версия Pulse

## Где живёт

- **На сайте:** отдельный раздел сайдбара (например, секция «Система» — «📖 База знаний»). Также — кнопки `?` рядом с настройками открывают конкретные статьи в модальном окне или в новой вкладке.
- **Публично:** `pulsechat.app/docs` (или `/help`, или `/kb`) — без авторизации, индексируется поисковиками.
- **Источник:** markdown/MDX-файлы в репо (например `docs/help/<section>/<article>.md`), рендерим через MDX-плагин. Скриншоты — в `docs/help/_assets/`.

**Почему markdown в репо, а не БД:**
- Версионируется в git (ревью PR-ами как код)
- Не теряется при миграциях
- Можно писать в любом редакторе
- Diff читается человеком
- Дешево (никакого CMS)

## Технически

**Стек предложения:**
- **Контент:** `docs/help/` в репо, .md/.mdx файлы с frontmatter (`title`, `slug`, `section`, `order`, `updated`, `related: [...]`)
- **Билд:** при `npm run build` сайта — папка `docs/help/` сканируется, генерируется индекс `help_index.json` + копируются ассеты в `Admin_SITE/public/help/`
- **Поиск:** клиентский — простой full-text по `help_index.json` (минифицируется до ~50–200 KB)
- **Рендер:** `react-markdown` или MDX, c подсветкой кода и кастомными компонентами (Alert, ScreenshotCarousel, Related, BadgePaid)
- **Backlinks:** скрипт при билде строит граф «эта статья упоминается в …»
- **URL:** `/docs/<section>/<slug>` + редиректы со старых slug в frontmatter

## Связи с остальным сайтом

- **Каждая страница модуля в админке** → кнопка `📖 Подробнее` → конкретная статья
- **Onboarding нового владельца** → ссылка «Прочти первые 3 статьи»
- **Раздел «Что произойдёт если выключить модуль»** в Хабе модулей → подгружает из base помощи
- **Поисковая строка сайта** ищет одновременно по контенту админки и по docs

## §6. Аргумент за «подвинуть раньше Биллинга»

**За «до Биллинга»:**
- Если человек платит — должен понимать ЗА ЧТО. Без docs тариф = «кот в мешке».
- На текущей фазе владельцы уже путаются (Витя в том числе). Help-center снимает поддержку лично с Ильи.
- SEO начинает работать на статьи через 2–3 месяца после публикации — лучше пораньше.

**За «после Биллинга»:**
- Продукт быстро меняется, docs устаревают.
- Без устоявшегося фичес-сета нечего документировать.

**Компромисс (если решим двигать раньше):**
- **MVP help-center** до Биллинга: 1 раздел «Старт» + 3 ключевых модуля (Экономика, Триггеры, Сообщества) с краткими статьями. Каркас + поиск.
- Полный обвес после Биллинга: все 13 разделов, видео-туториалы, кейсы.
