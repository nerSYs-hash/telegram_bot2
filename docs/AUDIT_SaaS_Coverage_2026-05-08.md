## Группа 3. **СПЕЦИАЛЬНЫЕ ПРОБЛЕМНЫЕ ЗОНЫ** (отдельно по запросу)

### 3.1 🔧 Восстановление данных по веткам (recovery / restore by branch)

**Текущее состояние:**
- ✅ `db_economy.rollback_econ()` — откат настроек экономики (через сайт)
- 🔧 BBS: `cleanup_bbs.py` есть, но это очистка, не восстановление
- 🔧 Лотерея: невозможно восстановить отменённую лотерею
- 🔧 Журнал: нет undo для удалённых записей
- 🔧 Транзакции: только `economy_cancellations` для эконом-движений, для других модулей нет
- 🔧 Press-release: есть `press_release_versions` (история версий), но нет UI «восстановить версию»
- ❌ Анкеты BBS — удалил случайно — финал, нет восстановления
- ❌ Триггеры — удалил → потерял
- ❌ Пользовательские профили — нет soft-delete
- ❌ Title пакеты — нет undo

**Проблема:** Нет единого паттерна. Каждый модуль решает (или не решает) восстановление по-своему.

**Что нужно:**

| Слой | Действие |
|---|---|
| **Архитектура** | Единая концепция: `soft_delete` (пометка `deleted_at`) + табл `audit_log` для всех изменений + UI «История раздела X» с кнопкой Restore. Не удалять физически в течение N дней. |
| **БД-схема** | Добавить `deleted_at TEXT NULL` ко всем тенантизируемым таблицам где имеет смысл (анкеты, триггеры, журнал, лотереи, бинго, титулы, посты, сообщения) |
| **Сайт** | Раздел «Корзина / История» по каждому модулю или общий — показывает удалённое за последние N дней с кнопкой «Восстановить» |
| **Бот** | Команды `/restore` для админа с интерактивным выбором |
| **Приоритет** | После завершения multi-tenancy. **Подпроект #5+ или отдельная итерация V1.18** |

### 3.2 🔧 Центр подключения (Connection Center)

**Текущее состояние:**
- 🔧 BBS: подключается через тематические темы (topic_id), настраивается через бот-команды
- 🔧 Журнал: подключается через настройку темы в `bot_chat_topics`
- 🔧 Bug-tracker: своя тема, своя логика
- 🔧 Реактор: тема `reactor_topic`
- 🔧 Стикерпак Pulse, баннеры, обложки — раскиданы
- 🔧 Branding: есть `branding_settings`, но интеграция модулей не централизована

**Проблема:** Каждый модуль (журнал, BBS, баг-трекер, реактор) подключается через **свою** настройку темы / чата. Нет одной точки «вот этот модуль подключён к этой теме в этом чате». Невозможно увидеть карту подключений в одном месте.

**Что нужно:**

| Слой | Действие |
|---|---|
| **БД-схема** | Единая таблица `module_bindings (workspace_id, module_key, chat_id, topic_id, is_enabled, settings_json)` — module_key = bbs / journal / bug_tracker / reactor / shipper / triggers / press_release / etc. |
| **Сайт** | Раздел «Подключения» — карточка на каждый модуль: «Подключён к чату X, тема Y, [настроить] [отключить]». Drag-n-drop куда подключить новый модуль. |
| **Бот** | При установке бота в чат → wizard «Какие модули вы хотите включить здесь?» |
| **Приоритет** | Связано с **Подпроектом #2 (Bot connection flow)** — оба про onboarding. Делать вместе. **Подпроект #2 расширить до Connection Center.** |
