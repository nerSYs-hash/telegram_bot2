# Puls Chat — Layout Spec (карта расположения)

> **Зачем.** `DESIGN_BRIEF` отвечает на «как выглядит» (цвет/токены/темы).
> Этот файл — «что где стоит»: расположение компонентов и кнопок по
> каждой странице. **Мост:** копируешь блок одной страницы в дизайн-
> вкладку (вместе с DESIGN_BRIEF) → она рисует layout по нашим зонам.
> Это контракт раскладки, НЕ реализация. Реализуем потом, по экрану.

---

## 0. Глобальные правила раскладки (для ВСЕХ страниц)

- **Контейнер:** `TwoColLayout`/`Section` shell (§11 брифа). Не верстать по месту.
- **Зоны страницы (сверху вниз):**
  1. **TopBar** (общий, не часть страницы): слева — название раздела;
     справа — `WorkspaceSwitcher` · тема-тумблер · профиль · выход.
  2. **PageHeader:** eyebrow (`text-[10px] uppercase tracking-widest --label`)
     + заголовок (`text-xl font-black`) + краткое описание. Справа в этой
     строке — **ОДНА primary-кнопка экрана** (главное действие). Вторичные —
     `secondary/ghost`, визуально тише, рядом или в `…`-меню.
  3. **Фильтр-строка** (если есть): `Tabs`/`Select`/`Search` — отдельной
     строкой под header, горизонтальный скролл на мобиле, верхний паддинг
     (чтобы активная пилюля `scale-105` не резалась).
  4. **Контент:** карточки/таблицы в сетке (1 кол моб · 2 кол ≥768 ·
     до 12-кол сетки десктоп, крупные блоки, много воздуха — North star Aaru).
  5. **Sticky:** метрик-шапки/тулбары — `sticky top`, остальное скроллится.
- **Иерархия действий (ui-ux-pro-max):** на экране **одна** primary-CTA.
  Деструктив (`danger`) — всегда визуально и пространственно отделён от
  обычных, не рядом с primary.
- **Цвет = смысл (§11):** акценты разделов — violet=ПР, amber=экономика,
  yellow=триггеры, blue=CTA, emerald=успех. Цвет только статус/раздел.
- **Пустые состояния:** `EmptyState` по центру блока (иконка-пульс +
  текст + 1 CTA «создать/добавить»), не пустой экран.
- **Drag-перекладка секций:** хват — `grip`-иконка слева сверху секции;
  строка-подсказка «перетащите за иконку» + кнопка «сброс» — над контентом,
  тоном `--label`, не кричит.
- **Мобайл:** всё в 1 колонку, primary-CTA уезжает под header на всю
  ширину; фильтры — горизонт-скролл; aside уходит вниз.

## 1. Dashboard / Статистика (стартовый экран)

- **PageHeader:** «Статистика» + период-`Tabs` (Сегодня/Неделя/Месяц…) —
  справа от заголовка primary нет (экран обзорный, read-only).
- **Зона A — Hero:** крупная карта «Индекс здоровья» на всю ширину
  (большое число display 56px, бейдж раздела, ℹ-кнопка справа-вверху,
  раскрытие субиндексов аккордеоном вниз).
- **Зона B — График:** `Card` на всю ширину, заголовок-eyebrow слева +
  счётчик-бейдж справа, area-chart, brush снизу.
- **Зона C — Метрики:** сетка 2×2 (моб) / 4× (десктоп) `StatRing`/
  metric-tile: иконка-чип сверху, лейбл, большое tabular-число.
- **Зона D — Банк:** одна акцент-карта (amber, экономика).
- **Зона E — Экспорт:** одна `secondary` кнопка «Excel» на всю ширину, низ.

## 2. Экономика

- **Sticky-шапка `EconomyHeader`:** строка из 5 метрик (иконка Lucide +
  лейбл + число), справа — «live»-пульс-точка. Прибита к верху.
- **Тулбар:** справа — `danger`-ghost «Отмены выплат» (вторичное,
  отделено). Поиск/фильтр категорий — слева, если нужен.
- **Контент — сетка категорий:** `EconomyCategoryCard` плитками
  (2 кол ≥768), у каждой: иконка+название слева, master-`Toggle`
  справа, значение, шеврон-раскрытие. Внутри раскрытой — `EconomyRow`
  список: лейбл · значение · действия (chart/cog) справа.
- **Редактор параметра:** НЕ «вылезающее окно». `Modal` по центру
  (backdrop blur), либо инлайн-`Section` раскрытием в строке. Решить
  единообразно (сейчас «вытаскивается» — это и чиним в #13).

## 3. Триггеры

### 3a. Список
- **PageHeader:** «Триггеры» + **Поиск** (широкий, на всю строку под
  header). Primary справа — нет; основное действие ниже.
- **Action-bar:** `secondary` «Статистика» слева · **primary
  «+ Создать триггер»** по центру/растянуто · `…`-меню справа.
- **Контент:** список `TriggerRow` — статус-точка, имя, условия-чипы
  кратко, `Toggle` вкл/выкл справа, клик → редактор.

### 3b. Редактор (полный экран)
- **Шапка:** «×» + имя триггера + **`Черновик`(secondary) ·
  `Запланировать/Сохранить`(primary)** справа. (primary один.)
- **Stepper** статусов под шапкой (Черновик→Запланирован→Опубликован).
- **2 колонки (`TwoColLayout`):**
  - **Слева — Условия:** карта «% шанс срабатывания» (слайдер) →
    `ConditionGroup` (чипы) → `DashedAdd` «добавить условие» →
    «добавить группу условий».
  - **Справа — Действия:** «лимит срабатываний» → `ActionGroup` →
    `DashedAdd` «добавить действие» → «добавить группу действий».
- **Низ — «Дополнительно»:** сегменты «Где срабатывает» (Везде/Чат/
  Личка), «На кого» (Все/Юзеры/Админы) — `ButtonGroup`-сегменты.
- **Выход:** confirm-`Modal` «несохранённые потеряны» (Выйти /
  Продолжить настройку — primary = остаться).

## 4. Пресс-релизы

### 4a. Список
- **PageHeader:** «Пресс-релизы» (violet) + **primary «+ Новый
  пресс-релиз»** справа. Status-`Tabs` (Запланир./Черновики/История/
  Отменённые/Ошибки) — строкой ниже.
- **Контент:** `PostCard` сеткой: заголовок + статус-пилюля, превью-
  текст, мета (дата · кол-во чатов). Клик → редактор.

### 4b. Редактор
- **Шапка:** «×» + «Новый пресс-релиз» + **`Черновик`(secondary) ·
  `Запланировать`(primary)** справа.
- **Stepper:** Черновик→Запланирован→Опубликован.
- **Секции (drag-перекладываемые, `Section`+grip):** Внутреннее имя →
  Медиа (сегменты Фото/Видео/GIF + слоты) → Содержимое (редактор
  `Редактор/Код` + тулбар + `%плейсхолдеры%` справа + Превью) → Куда+
  Когда (`КУДА` селектор чатов / `КОГДА` календарь) → Inline-клавиатура
  (ряды кнопок + `DashedAdd`) → Настройки публикации (collapsible).

## 5. Журнал

- **PageHeader:** «Журнал» + фильтр-`Tabs` по типам событий (строкой
  ниже, гориз-скролл, верхний паддинг).
- **Контент:** лента `LogCard`: аватар + имя + время + статус-тег
  (семантический цвет) справа + шеврон-раскрытие. Раскрытое тело:
  текст события + ряд кнопок-действий (Написать в ЛС primary;
  бан/мут/разбан — `danger`/semantic, отделены).

## 6. Система / Настройки

- Стопка `Section`-карт, каждая = блок:
  1. **Курс Пульса:** крупное число слева + edit-кнопка-иконка справа.
  2. **Администраторы:** строка добавления (input + primary «Добавить»)
     → список (строка: @user + бейдж роли + `danger`-иконка удалить).
  3. **Функции бота:** список строк «название + `Toggle`».
  4. **Стиль цитат:** превью-блок + строки настройки (цвет/режим).
- Один primary на блок максимум; деструктив отделён.

## 7. Права / RBAC

- **Выбор роли:** сверху сегменты-карты ролей («Зам владельца» /
  «Администратор») — активная = bg-cta, счётчик «N из M разрешений».
- **Контент:** список ресурсов-`Section` (Триггеры/Шиппер/ПР…),
  каждая: иконка+название+«N из M действий» + master-`Toggle`(ВКЛ/ВЫКЛ)
  справа + раскрытие. Внутри — сетка `Checkbox`-карт действий 2 кол
  (Просмотр/Создание/Редактирование/Удаление/Вкл-выкл), цвет действия
  семантический (удаление — danger-текст).

## 8. Sidebar (§5a — структурно, фаза #13 + #7)

- Ширина expanded **248** / collapsed **80** (spring-collapse).
- Сверху: бренд-марка (пульс-лого) + вордмарк; ниже — поиск.
- Группы пунктов с лейблами (Мониторинг/Модули/Сервис). Пункт: иконка
  20px + лейбл; active = заливка + иконка в `--cta`; бейдж-счётчик
  справа. **Collapsed: бейдж = точка в углу иконки, НЕ число (#7).**
  Лейблы скрыты, hover → тёмный тултип.
- Футер прибит к низу: тема-тумблер → строка юзера (аватар+имя+email+
  logout). Collapsed — только аватар.

## 9. ЛК владельца / Сообщества (нет в дизайне — собрать из T1/T2)

- **WorkspaceList:** карты сообществ (сетка), у каждой: имя, статус,
  метрики кратко, клик → WorkspacePage. `DashedAdd` «новое сообщество».
- **WorkspacePage:** header сообщества + primary «Подключить чат»;
  список чатов (роль-`Select` главный/админ/журнал, статус-пилюля
  подключён/отключён/реконнект — §14), помощники, `InviteMemberModal`.
- Owner-only действия (удаление) — `danger`, отделены, по гейту прав.

## 10. Как пользоваться (мост в дизайн-вкладку)

1. Берёшь блок ОДНОЙ страницы (раздел 1–9) + при желании раздел 0.
2. Вставляешь в дизайн-вкладку **вместе с `DESIGN_BRIEF`** (скин-контракт).
3. Просишь: «Нарисуй layout этой страницы по зонам, обе темы, десктоп
   1440 + мобайл 390. Компоненты — из дизайн-системы (T1/T2)».
4. Возвращаешь артефакт — мы по нему перекладываем реальный экран
   (фаза #13, поэкранно, behavior-preserving где можно).

> Парность: `DESIGN_BRIEF` = как выглядит · `LAYOUT_SPEC` (этот) = что
> где стоит. Вместе = полный контракт страницы для отрисовки.
