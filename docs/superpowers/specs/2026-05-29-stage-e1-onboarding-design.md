## 1. Контекст и проблема

Текущий флоу подключения (`handlers/bot_membership.py`, ветка #6) при добавлении
бота владельцем, у которого уже есть сообщества, выводит **в групповой чат**
inline-кнопки: по одной на каждое сообщество × 3 роли (`main`/`admin`/`journal`)
+ «новое сообщество». При N сообществах это `N×3 + 1` кнопок.

Две проблемы:
1. **Стена кнопок («портянка»)** — не масштабируется. 10 сообществ = 31 кнопка.
2. **🔒 Утечка приватности** — названия ВСЕХ сообществ владельца публикуются в
   групповом чате, где сидят посторонние участники.

**Эталон (ChatKeeper):** в Telegram пользователь **не выбирает ничего**. Бот в
группе кидает короткое самоудаляемое приветствие + кнопку «Настроить» (LoginUrl),
владельцу в личку — «группа X подключена». Вся организация (роли, группировка,
настройки) — на сайте.

## 2. Цель E1

Подключение группы всегда «просто работает», без выборов в чате, без утечки.
Это первая фаза; раздача ролей и группировка чатов в сообщества уезжает в **E2**
(Центр подключений на сайте, отдельная спека).

### Модель ролей (договорённость, реализуется в E2, фиксируется здесь)

Роли — **не вопрос в групповом чате, а слоты на сайте**:
- `main` — группа, куда добавили бота (авто, путь 1, **это E1**);
- `journal` (канал) / `admin` — объявляются на сайте → сайт ведёт «подключи под
  слот канал/чат» → привязка диплинком `t.me/Bot?startchannel=...` с зашитым
  `ws_id`+роль (механизм **A**). Это **E2**.

## 3. Объём E1 (что меняем сейчас)

Только путь 1 (бота добавили в группу из Telegram). Файл `handlers/bot_membership.py`.

### 3.1 Новое поведение `on_bot_added_to_chat`

| Ситуация | Сейчас | E1 |
|---|---|---|
| Чат уже привязан к **моему** ws | «уже подключён» | без изменений |
| Чат привязан к **чужому** ws | сообщение + `leave_chat` | без изменений |
| Добавил **незарегистрированный** | reject + `leave_chat` | **гейт убран** — подключаем; вход через OAuth-кнопку сам создаёт сессию |
| Добавил владелец, **есть сообщества** | 🔴 портянка `N×3` кнопок | ✅ авто-создать **новый** ws (`role='main'`), без вопросов |
| Добавил, сообществ нет | авто-создать ws | без изменений |
| Reconnect soft-removed чата | сообщение в чат | без изменений (опц.: +DM владельцу) |
| Канал (`chat.type == 'channel'`) | тихо пропустить | без изменений (каналы — через E2) |

**Итог:** любая группа/супергруппа с ботом → авто-создаётся workspace, `role='main'`,
`owner = from_user.id`. Ноль inline-выборов в чате. Ветки #6 (портянка) и #5
(гейт регистрации) удаляются.

### 3.2 Сообщения

**В группе** (самоудаляемое через ~120 c):
```
👋 Привет! Я Puls_bot — статистика, экономика и модерация чата.
⚠️ Для полной работы дай мне права администратора.
🔗 Поддержка · Новости · Инструкция
Это сообщение исчезнет через пару минут, чтобы не засорять чат.
[ ⚙️ Настроить Puls_bot ↗ ]    (LoginUrl)
```
Удаление: `context.job_queue.run_once(_delete_msg, 120, data={chat_id, message_id})`.
Если job_queue недоступен или удаление падает — логируем и игнорируем (не критично).

**В личку владельцу** (во ВСЕХ путях создания/привязки — сейчас DM есть только в
ветке #7):
```
✅ Подключил чат «X» к твоему кабинету.
Зайди настроить — роли, модули, статистика:
[ ⚙️ Открыть кабинет ↗ ]    (LoginUrl)
```
DM может не дойти (юзер не начинал диалог с ботом) — оборачиваем в try/except,
приветствие в группе остаётся основным каналом.

> **Тексты — черновик.** Илья согласовал тон, формулировки причёсываем перед
> выкатом (ссылки Поддержка/Новости/Инструкция — реальные URL подставить).

### 3.3 Тумблер + FAQ (дом-правило «код + тумблер + FAQ»)

- Новое поведение — за существующим флагом `CONNECT_FLOW_V2` (расширяем смысл).
  **OFF = старая портянка байт-в-байт** (регресс-гарантия).
- LoginUrl-кнопки требуют `LOGIN_URL_BUTTON=ON` (включается на проде в приёмке
  вместе с `I_WS_RBAC` T9).
- FAQ: пункт «Как подключить чат и войти в кабинет».

## 4. Edge cases

- **Гонка** (два MY_CHAT_MEMBER подряд) — уже защищено `old.status in (member, administrator)` ранним выходом; сохраняем.
- **DM не доставлен** — try/except, не валим флоу.
- **job_queue нет** — try/except вокруг планирования удаления.
- **Канал** — по-прежнему ранний `return` (E2).
- **Чужой ws** — по-прежнему сообщение + leave (изоляция).

## 5. Тесты (`tests/test_bot_membership.py`)

1. Владелец с ≥1 ws добавляет бота → **нет** inline-кнопок, создан новый ws
   `role='main'`, DM владельцу отправлен.
2. Незарегистрированный добавляет → чат подключён, `leave_chat` **не** вызван.
3. Самоудаление приветствия запланировано (`run_once` вызван с ~120 c).
4. Флаг `CONNECT_FLOW_V2=OFF` → старое поведение (портянка) — регресс байт-в-байт.
5. Чужой ws → сообщение + leave (без изменений).

## 6. Критерий приёмки E1

Добавляю бота в любую группу (даже имея другие сообщества) → **в чате нет списка
кнопок**, приходит короткое приветствие, оно само исчезает через пару минут, мне
в личку падает «подключил чат X» с кнопкой в кабинет. Чат виден на сайте как новый
workspace с ролью `main`. Имена других моих сообществ нигде в группе не светятся.
